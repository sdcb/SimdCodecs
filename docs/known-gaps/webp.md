# WebP：支持情况与已知缺口

条目约定（“不支持”“门面不提供”“未调优”）和跨格式的门面限制见 [总览](../known-gaps.md)。表中 ✅ 支持，⚠️ 部分支持（见说明），❌ 不支持。

## 支持情况

### 解码

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 有损（VP8） | ✅ | 与 libwebp 1.6.0 逐字节一致 |
| 无损（VP8L） | ✅ | 同上 |
| 透明（ALPH 平面、VP8L alpha） | ✅ | alpha 平面可选在第二个线程解码 |
| 动画：合成整幅画布、跳转、帧时长 | ✅ | 门面 `TryOpenFrames`；包内另有按时间戳跳转和帧矩形 |
| VP8X 扩展格式 | ✅ | |
| 保留的 VP8 色彩空间标志 | ❌ | 规范保留值 |
| `TryDecodeInto` 直写调用方缓冲区 | ✅ | |

### 编码

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 无损静态图（力度 0–9） | ✅ | 默认力度比 libwebp 默认小 1.4%，吞吐约为它的 1.14× |
| 有损静态图（质量 0–100，力度 0–6） | ✅ | 对 libwebp 默认 BD-rate −6.2%（PSNR-Y） |
| 有损 + 透明（ALPH） | ✅ | alpha 默认无损，`AlphaQuality` 可降级 |
| 动画（有损、无损或逐帧取小） | ✅ | 只写变化矩形 |
| trellis 量化 | ❌ | |

### 元数据

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 读取 ICC、Exif、XMP | ✅ | |
| 写入 ICC、Exif、XMP | ✅ | 输出 VP8X |

### 门面与性能

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 原生缩放解码 | ⚠️ | 仅有损（VP8）静态图：解码时逐行做 box 缩小，不生成全尺寸图；无损、动画仍是整幅解码后 box 缩小 |
| 区域按需解码 | ⚠️ | 仅有损静态图：只转换区域覆盖的行和列，区域最后一行所在的宏块行之后提前停止；ALPH 平面仍整幅解码。无损、动画仍是整幅解码再裁剪 |
| 解码已调优 | ✅ | 照片类不透明有损与 libwebp 持平（0.87–1.13×），其他类别更快 |
| 编码已调优 | ✅ | 默认设置下无损和有损的体积都小于 libwebp，速度相当；个别带透明的图仍慢约 10% |

## 已知缺口与局限

- **编码器**：无损（VP8L）和有损（VP8）静态图及动画，有损图带透明时写 ALPH 平面，ICC / EXIF / XMP 可以写入（此时输出 VP8X 扩展格式）。
- **动画编码**：5 个合成序列上，无损总字节是 `img2webp -lossless` 的 0.931×，有损对 `img2webp -lossy` 的 BD-rate 为 −10.1%。但 sprite 和 alpha-sprite 两个序列的无损输出比 img2webp 大 3% 和 9%。fade 序列算不出 BD-rate：我们的有损 曲线整体比 img2webp 的质量高（q90 时字节数相近，PSNR 高 6.5 dB），两条曲线没有重叠区间，所以这一项不计入均值。
- **有损编码**：AMD Ryzen 7 5800X 上 12 张不透明基准图，默认力度（4）对 libwebp 默认（method 4）的 BD-rate 为 PSNR-Y −6.2%、SSIM-Y −4.8%，每张图两项都为负；q75 速度约为它的 1.07×（18.6 vs 17.4 MP/s）。高码率一端 （q ≥ 70）也是 −5.4% / −5.5%。还没有 trellis 量化。
- **有损 + 透明**：3 张带透明的基准图，可见像素 PSNR-RGB 的 BD-rate 为 −4.5%（alpha 逐字节一致），但 sticker 一张 是 +0.8%（ALPH 比 libwebp 大约 3%）。q75 时三张合计耗时约为 libwebp 的 0.96×；photo-alpha 和 screen-alpha 更快， sticker 仍慢约 10%（它的 alpha 平面要靠预测器，直接编码那一路的代价解析最贵）。
- **无损编码**：AMD Ryzen 7 5800X 上 14 张基准图合计，默认力度（6）比 libwebp 默认小 1.4%，速度约为它的 1.14× （2.92 vs 2.56 MP/s）；力度 9 小 1.7%，但只有它速度的 0.37×。`cwebp -z 9` 仍比我们的力度 9 小 1.1%（它慢约 7 倍）。
- **有损静态图的区域 / 缩放解码提前停止，不校验其余码流。** 设了 `Region` 或 `ScaleDenominator` 时，有损（VP8）静态图逐个宏块行解码，色度上采样仍按整行做（fancy 上采样要读相邻列），YUV → RGB 只转换区域的列，再按 `TryDecode` 的布局（不透明 RGB，带透明 RGBA）送进 box 滤波器，最后转换成目标像素格式，所以输出与整幅解码、box 缩小、裁剪、转换逐字节一致。区域下方的宏块行不做熵解码，那里损坏或截断的码流不会报错，整幅解码则能解出（截断部分读作 0 比特）。帧头、分区表等区域之上的错误照常返回 false。ALPH 平面仍整幅解码，带透明时多占宽 × 高字节。AMD Ryzen 7 5800X 上 1920×1080：顶部 640×270 区域约为整幅解码再裁剪的 0.18×，底部约 0.72–0.83×，1/2–1/8 缩放约 0.68–0.93×；工作内存从约 15 MiB 降到 0.3 MiB（带透明 3.1 MiB，即 alpha 平面），见 [基准结果](../../benchmarks/Sdcb.SimdCodecs.Webp.Benchmarks/optimization/scaled-region-2026-11-08-amd-ryzen-7-5800x.md)。`TryGetClosestSize` 仍返回存储尺寸。
- **保留的 VP8 色彩空间标志不支持**（规范保留值）。
- **性能**：在接近照片内容、不带 alpha 的有损文件上与 libwebp 持平（0.87–1.13×），没有全面领先；其他类别更快， 见 [WebP 基准结果](../../benchmarks/Sdcb.SimdCodecs.Webp.Benchmarks/optimization/m4-final-2026-10-25-amd-ryzen-7-5800x.md)。
