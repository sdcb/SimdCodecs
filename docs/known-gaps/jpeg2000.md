## 已知缺口与局限

- **只支持 Part 1（T.800），定位是 PDF 里的 `/JPXDecode`。** 多 tile、tile-part、自定义 precinct、 五种进度顺序、SOP / EPH 标记、JP2 调色板（`pclr` + `cmap`）都已支持。
- **不支持**：
  - 进度顺序变更（POC）；
  - 打包的包头（PPM、PPT）；
  - 感兴趣区域（RGN / MAXSHIFT）；
  - 在 tile-part 头里覆盖主头参数的标记（COD / COC / QCD / QCC）；
  - code-block 样式里的选择性旁路（0x01）、每个 pass 单独终止（0x04）、垂直因果上下文（0x08）。 上下文重置（0x02）、可预测终止（0x10）、分段符号（0x20）已支持；
  - 分量子采样、带符号分量。
- **分量位深最多 16 位，且所有分量位深必须相同**；经调色板映射后的各通道位深也必须相同。
- **JP2 通道定义盒（`cdef`）已支持**：颜色通道按色彩空间顺序（Asoc 1、2、3……）重排，不透明通道放在最后，`Jpeg2000Image.Channels` / `Jpeg2000Info.Channels` 报告每个通道的类型；Typ 2（预乘不透明度）由门面用整数公式还原，没有 `cdef` 的 4 分量图（可能是 CMYK）仍然拒绝。
- **门面只呈现灰度（1）、灰度 + alpha（2）、RGB（3）、RGB + alpha（4）、且不是 sYCC 的图像**；其他情形门面返回 `false`，`Jpeg2000Decoder.Decode` 仍会返回全部通道：没有 `cdef` 的 2 或 4 分量、sRGB / 灰度以外的枚举色彩空间（CMYK、CIELab 等）、只作用于某一颜色的不透明通道、多个不透明通道、用途未指定（Typ 65535）的通道、色彩空间与颜色通道数不符。
- **门面的缩放（`ScaleDenominator`）在原生范围内就是分辨率缩减**：不超过 2^分解层数 的 2 的幂与 `opj_decompress -r` 一致，被省略的层不做熵解码；更大的分母先按最大缩减解码，再用 box 滤波缩小。SIZ 图像偏移非零的图没有原生缩减（参考网格上的取整可能与 ⌈w/d⌉ 差一个像素），每个分母都是整幅解码后 box 缩小；需要参考网格上的缩减时仍可直接调用 `Jpeg2000Decoder.Decode(data, reduce)`。
- **真实文件回归**：issue #1 附带的 16 个 JPEG 2000 文件（来源和许可不明，不进仓库）全部与 `opj_decompress` 一致（5/3 逐样本相同，9/7 最多差 1）。改动解码器后按 `Issue1Jpeg2000CorpusTests` 的说明下载并跑一遍。
- **已有基准测试，单线程性能仍待调优**：基准项目 `Sdcb.SimdCodecs.Jpeg2000.Benchmarks` 在 `results/` 记录了基线与多线程结果。单线程纯托管解码耗时约为 libopenjp2 纯 C 核心的 1.9×~2.2×；解码默认并行（同一 tile 内的 code-block、小波的行与列条带、分量变换、电平移位按逻辑处理器数分配线程，结果与串行逐位相同），16 线程时约为 libopenjp2（同样 16 线程）的 1.15×~1.75×。EBCOT 条带位掩码快速跳过与系数重构缓冲区复用尚未实现；tile 之间仍串行解码（内存上限是一个 tile 的工作集）。
