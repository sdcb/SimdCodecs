# ICO / CUR：支持情况与已知缺口

条目约定（“不支持”“门面不提供”“未调优”）和跨格式的门面限制见 [总览](../known-gaps.md)。表中 ✅ 支持，⚠️ 部分支持（见说明），❌ 不支持。

## 支持情况

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 图标（`.ico`）和光标（`.cur`） | ✅ | 光标带热点坐标 |
| PNG 图像 | ✅ | 解码成 8 位 RGBA，16 位丢低 8 位 |
| DIB 图像（全部位深，带 AND 掩码） | ✅ | 压缩的 DIB 不支持 |
| alpha | ✅ | 32 位像素的 alpha，否则用 AND 掩码 |
| 目录里的每一张 | ✅ | 门面 `TryOpenFrames` 每张一页；`TryDecode` 给最大、最深的一张 |
| 多尺寸编码 | ✅ | PNG、32 / 24 / 8 / 4 / 1 位 DIB |
| 编码时缩放 | ❌ | 各尺寸由调用方准备 |
| 动画光标（`.ani`） | ❌ | |
| 已调优 | ✅ | DIB 走 BMP 包的 SIMD 行内核 |

## 已知缺口与局限

- **每张图都解码成 8 位 RGBA**，16 位的 PNG 图像会丢掉低 8 位。
- **不支持压缩的 DIB 图像**（Windows 本身也不接受）。
- **编码器不缩放**：各尺寸的图像要由调用方准备好；每张最大 256×256（解码不限尺寸，上限 2^28 像素）。
- **不支持动画光标（`.ani`）。** 它是 RIFF 容器，不是 ICO 目录。
- **门面的 `TryDecode` 只返回最大、位深最高的一张**；要拿其他尺寸，用 `TryOpenFrames` 或 `IcoDecoder`。
