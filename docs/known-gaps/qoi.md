# QOI：支持情况与已知缺口

条目约定（“不支持”“门面不提供”“未调优”）和跨格式的门面限制见 [总览](../known-gaps.md)。表中 ✅ 支持，⚠️ 部分支持（见说明），❌ 不支持。

## 支持情况

| 功能 | 状态 | 说明 |
|---|:-:|---|
| RGB、RGBA 解码 | ✅ | 完整实现规范 |
| 色彩空间字节（sRGB / 线性） | ✅ | 报告给 `ColorEncoding`，不改变像素 |
| `TryDecodeInto` 直写调用方缓冲区 | ✅ | 任意 8 位布局，零分配 |
| 编码（RGBA、BGRA、RGB、BGR、灰度输入，任意行跨度） | ✅ | 到数组或流 |
| 原生缩放解码 | ❌ | |
| 区域解码 | ⚠️ | 整幅解码再裁剪 |
| 已调优（解码和编码） | ✅ | 只和 ImageSharp 比过：解码约 0.29×、编码约 0.49× |

## 已知缺口与局限

- **没有原生竞品参照。** 基准只和 ImageSharp 3.1.12 比（解码约 0.29×、编码到流约 0.49×）；QOI 没有现成的原生库二进制， 没有和参考实现 qoi.h 比过速度。解码受规范本身的串行性限制（索引哈希和游程逐像素依赖前一个像素），没有 SIMD 内核。
- 规范没有定死的几处（3 通道图像里的 alpha、超出图像的游程、结尾标记）列在包的 README 里。
