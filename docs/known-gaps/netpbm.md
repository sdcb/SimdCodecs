# Netpbm（PBM / PGM / PPM / PAM / PFM）：支持情况与已知缺口

条目约定（“不支持”“门面不提供”“未调优”）和跨格式的门面限制见 [总览](../known-gaps.md)。表中 ✅ 支持，⚠️ 部分支持（见说明），❌ 不支持。

## 支持情况

### 解码

| 功能 | 状态 | 说明 |
|---|:-:|---|
| PBM、PGM、PPM 的 ASCII（P1–P3）和二进制（P4–P6） | ✅ | |
| maxval 1–65535 | ✅ | 非 255 / 65535 时按比例缩放到满量程 |
| PAM（P7），1–4 通道 | ✅ | DEPTH 大于 4 拒绝 |
| PFM 浮点灰度 / RGB | ✅ | 不能投影到 8 位布局 |
| 原生 8 / 16 位或浮点样本 | ✅ | |
| `TryDecodeInto` 直写调用方缓冲区 | ✅ | 任意 8 位布局，零分配，SIMD 行内核 |
| 一个文件里的多张图 | ❌ | 只读第一张 |

### 编码

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 所有格式，ASCII 或二进制 | ✅ | |
| 8 / 16 位，1–4 通道，任意布局和行跨度 | ✅ | |
| PFM | ✅ | |
| 写入流 | ✅ | |

### 门面与性能

| 功能 | 状态 | 说明 |
|---|:-:|---|
| 原生缩放解码 | ❌ | 可用，整幅解码后 box 缩小 |
| 区域解码 | ⚠️ | 整幅解码再裁剪 |
| 已调优（解码和编码） | ✅ | 只和 ImageSharp 比过：解码约 0.23×、编码约 0.54× |

## 已知缺口与局限

- **只读文件里的第一张图**；后续的图被忽略，门面也不把它们当作多帧。
- **PFM 不能解码成 8 位布局**：浮点样本需要色调策略，`TryDecodeInto` 返回 false，`DecodeTo` 抛 `NotSupportedException`； 用 `PixelConverter.StretchToRgba8` 得到可看的图。PFM 头里 scale 的绝对值只报告，不应用。
- **PAM 的 DEPTH 只支持 1–4**；更多通道的 PAM 会被拒绝。
- **原始 8 位格式编码到流**基本是内存拷贝，耗时在 0.03–0.2 ms 量级，与 ImageSharp 的相对比值在不同轮次间波动较大（0.5×–1.8×）。
- ImageSharp 3.1.12 读写 16 位 PPM 时按小端（低字节在前），而 Netpbm 规范和 ImageMagick 都是大端；所以 16 位用例不和它计时比较。
